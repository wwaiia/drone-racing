# ТЗ: Агрегатор соревнований по дрон-рейсингу

Версия: 1.0 · Тип: MVP (12–16 недель до прод-релиза)

---

## 1. Общее описание

Веб-сайт-агрегатор, автоматически собирающий информацию о предстоящих соревнованиях
по гонкам дронов из открытых источников (ФГДР, региональные федерации, Telegram/VK
сообщества), структурирующий её и предоставляющий пользователям два режима просмотра:
по регионам (карта/список) и единый список крупных/всероссийских стартов.

### Ключевые сущности
- **Событие (Event)** — соревнование: название, дата, география, статус, призовой фонд, ссылки.
- **Источник (Source)** — канал/паблик, из которого извлечено событие.
- **Сырой пост (RawPost)** — необработанный текст поста (хранится для аудита и переобработки).

### Пользовательские роли
- **Гость** — просмотр, фильтрация. Без обязательной регистрации (регистрация — этап 2, только для подписок/уведомлений).
- **Администратор** — просмотр очереди модерации, правка/аппрув событий, управление источниками.

## 2. Архитектура и сбор данных (парсинг)

### 2.1. Общая схема (5 слоёв)

```
[Источники]                 [Коллекторы]         [Хранилище]        [LLM-извлечение]     [API/Фронт]
Telegram-каналы   ──cron──▶ Telethon- ┐
VK-паблики        ──cron──▶ vk_api    ├─▶ raw_posts ──▶ extractor ──▶ events       ──▶ REST/SSR
RSS/сайты ФГДР    ──cron──▶ http+bs4  ┘   (дедуп)       (LLM+regex)   (moderation)  ──▶ карточки/карта
```

Принцип: **сбор и извлечение разнесены**. Коллектор только скачивает текст и пишет
`raw_posts`; извлечение полей — отдельный шаг. Это позволяет менять «мозг» экстракции
(промпты, модели) без повторного опроса источников.

### 2.2. По каждой платформе

| Платформа | Метод интеграции | Обоснование | Лимиты/риски |
|---|---|---|---|
| **Telegram (публичные каналы/чаты)** | **Telethon** (MTProto, user-аккаунт) | Bot API не умеет читать чужие каналы; Telethon даёт полную историю каналов, работает через прокси | Нужен user-аккаунт + API_ID/API_HASH (my.telegram.org); обязательный SOCKS5-прокси для РФ-хостинга; не чаще ~1 запроса/сек |
| Telegram (альтернатива) | tgstat API (платно) | Официальный, без user-аккаунтов, есть поиск по постам | Цены от ~$20/мес; для MVP необязателен |
| **VK** | Официальный **VK API** (`wall.get`, `groups.search`, сервисный токен) | Полностью легитимно, стабильные версии | 20 req/s сервисным токеном — достаточно |
| Сайты/новостные страницы ФГДР | HTTP + BeautifulSoup / RSS при наличии | Сайты могут не иметь API | Меняем селекторы раскладками сайтов; парсер под каждый домен |

### 2.3. Дедупликация и сырые посты
`raw_post` уникален по `hash = sha256(platform + channel_id + post_id)`.
Повторная загрузка поста не создаёт дубль; при изменении текста поста создаётся новая
версия, старая помечается `superseded`.

Дедуп на уровне событий: дубль = совпадение нормализованного названия + даты + региона
(см. §4.4) — склеивается в одну карточку со списком источников.

### 2.4. LLM-экстракция (ИИ-агент) — ДА, но с гвардами

Сырой текст поста («22 ноября в Липецке на аэродроме пройдут открытые гонки ФГДР,
регистрация в закрепе до 15.11, призовой фонд 100 000 ₽…») вообще не является JSON —
здесь уместна LLM-экстракция в строгую структуру:

```
extractor → LLM (structured output / function calling, дешёвая модель класса
gpt-4.1-mini / gemini-flash / локальная qwen) → JSON-схема → валидация (pydantic) →
event с полем confidence (0..1) → confidence < 0.55 ИЛИ незаполненные
обязательные поля → очередь ручной модерации.
```

- **Схема вывода LLM** строго соответствует БД (см. §4), с enum'ами статуса/типа.
- **Regex-фоллбеки** перед LLM: даты (`\d{1,2}[./ ]\d{1,2}`), суммы (`\d[\d ]{3,}\s*(₽|руб|тыс)`),
  ссылки (`/регистрац|t\.me|forms|старт`) — 60–70% постов извлекаются бесплатно,
  LLM зовётся лишь для остальных.
- **Догадывание дат**: посты часто без года — экстрактор берёт ближайшую будущую дату
  относительно дня публикации; хранит `date_confidence` и источник допущения.
- **Классификация типа** (региональное / общее): явные маркеры («чемпионат России»,
  «ФГДР», «этап Кубка», «межрегиональ», «всероссийск») → `national`, иначе LLM-классификация
  + админом.
- **Стоимость**: при потоке ~200–500 постов/нед. даже платный LLM — копейки;
  для нулевых затрат возможен локальный вариант (Ollama + qwen2.5-7B) — ухудшит качество.

**Итог по архитектуре**: Telethon/vk_api сборщики (Python), APScheduler-кроны,
raw_posts → гибрид regex+LLM экстрактор → Postgres → модерация → выдача.

## 3. Стек технологий (рекомендация для MVP)

### Основной вариант (рекомендуемый)

| Слой | Технология | Почему |
|---|---|---|
| **Бэкенд + парсеры** | **Python 3.12 + FastAPI** | Telethon — Python; парсеры, экстрактор и API в одном рантайме; быстрые имплементации |
| Планировщик | APScheduler (внутри FastAPI) | 3 джобы (tg/vk/extract) — отдельный Celery/Redis на MVP не нужен |
| **БД** | **PostgreSQL 16** (+ SQLAlchemy 2.0 + Alembic) | Реляционные данные, транзакции, полнотекстовый поиск по кириллице (rus tsvector), PostGIS «на вырост» для координат площадок |
| **LLM** | OpenAI-compatible API (любая дешёвая модель) через `openai` SDK, structured outputs | Заменяемость провайдера |
| **Фронтенд** | **Next.js 15 (App Router) + TypeScript + TailwindCSS + shadcn/ui** | SSR/ISR для SEO (главная цель трафика — гугл/яндекс по «гонки дронов <город>»), готовые компоненты, Vercel/свой VPS |
| Карта | **Yandex Maps JS API** | Точность по субъектам РФ и городам выше OSM-плиток для рунета; фоллбек react-leaflet |
| Состояние/данные | TanStack Query (фронт), fetch к /api | Минимум бойлерплейта |
| Админка | Простые CRUD-страницы в Next.js + секрет | Не тащим Django-admin на MVP |
| Инфра | Docker Compose: `api`, `db`, `nginx`, `frontend` (или Next.js на Vercel + api на VPS в Нидерландах) | Прокси для Telethon живёт в compose |
| Мониторинг | Sentry (бэк+фронт) + простой uptime-пинг | Обязательно: парсеры ломаются незаметно |

### Альтернатива при команде из 1 человека и минимальном бюджете
- `Next.js 15 fullstack` (API-роуты на Node) + **GramJS** (Node-порт Telethon) вместо
  FastAPI — один репозиторий, один деплой; минус: GramJS сырее Telethon, а Py-экстрактор
  придётся вызывать как микросервис. Для быстрого прототипа — ок, для продакшена — второй вариант надёжнее.
- Mongo вместо Postgres — НЕ рекомендуется: фильтрация по регионам/датам/статусам
  и аналитика удобнее в SQL, миграции схемы с LLM-извлечением неизбежны.

### Что НЕ делаем в MVP
- Личный кабинет, OAuth, платежи, push-уведомления, мобильные приложения, авто-агрегация рейтингов пилотов.

## 4. Структура базы данных

### 4.1. `regions` (справочник субъектов РФ)
```sql
id            serial PK
name          text NOT NULL           -- «Липецкая область»
federal_district text NOT NULL       -- «ЦФО»
center_city   text
lat / lng     numeric(9,6)            -- центр субъекта для карты
slug          text UNIQUE             -- 'lipetskaya-oblast'
```

### 4.2. `sources`
```sql
id            serial PK
platform      text NOT NULL          -- 'telegram' | 'vk' | 'web'
external_id   text                    -- channel_id / group_id / domain
title         text
url           text
tier          text NOT NULL DEFAULT 'regional'  -- 'federal' | 'regional' | 'community'
is_active     boolean DEFAULT true
last_scraped_at timestamptz
fail_count    int DEFAULT 0
```

### 4.3. `raw_posts`
```sql
id                 bigserial PK
source_id          int REFERENCES sources
external_post_id   text                 -- tg message_id / vk post id
hash               text UNIQUE          -- sha256(platform:source:post)
text               text
posted_at          timestamptz
assets             jsonb                -- [{type:'photo'|'doc', url,...}] (афиши полезны админу)
processed          boolean DEFAULT false
extracted_json     jsonb                -- сырой вывод LLM для дебага
```

### 4.4. `events` — главная таблица

Обязательные поля помечены ★.

```sql
id              bigserial PK

-- Идентичность
title           text ★                  -- «Открытые гонки ФГДР — Липецк»
organizer       text                    -- «РОО ФГДР Липецкой области»
description     text

-- Дата/время (примерная допустима)
event_date      date        ★           -- эвристика: если год в посте не указан — ближайшая будущая
event_time      time                    -- nullable
date_time_precision text DEFAULT 'exact' -- 'exact'|'day'|'month'|'approx'
date_modified_at timestamptz            -- когда последний раз переносили (польз. видит «перенесено с …»)

-- География
region_id       int REFERENCES regions ★
city            text ★
venue           text                    -- «аэродром Липецк-Южный», nullable
lat / lng       numeric(9,6)            -- геокодинг (Яндекс Geocoder), для точек на карте

-- Классификация
event_type      text NOT NULL DEFAULT 'regional'  -- 'regional' | 'national'
                  -- national = всеобщий/крупный; regional = в конкретной области
discipline      text DEFAULT 'fpv-race' -- 'fpv-race' | 'freestyle' | 'time-trial' | 'other' (опционально)

-- Статус
status          text NOT NULL ★        -- enum:
                  -- 'anons'                     — анонс (дата есть, регистрации нет)
                  -- 'registration_open'         — регистрация открыта
                  -- 'registration_closed'       — набор закрыт, старт впереди
                  -- 'ongoing'                   — идёт сейчас
                  -- 'finished'                  — завершено
                  -- 'cancelled' | 'postponed'
auto_status     boolean DEFAULT true    -- крон сам обновляет: open→closed по дате, ongoing/finished по event_date

-- Призовой фонд
prize_fund_amount   numeric(12,2)       -- nullable; 0 = «без призового фонда»
prize_fund_currency text DEFAULT 'RUB'
prize_fund_note     text                -- «Призовой фонд 100 000 ₽, 1-е место — квадроцикл»
prize_fund_visibility text DEFAULT 'hidden'  -- 'hidden'|'none'|'amount'|'tbd'  → управляет плашкой карточки
                           --   hidden  — не упомянут в источнике → плашка «Уточняется» (или без плашки)
                           --   none    — явно «без призового фонда»
                           --   amount  — сумма; выделяется золотой плашкой
                           --   tbd     — «призовой фонд будет объявлен»

-- Ссылки
registration_url   text ★              -- «Перейти к регистрации» (может быть ссылкой поста)
source_url         text NOT NULL       -- «Подробнее об ивенте» — ссылка на пост/новость
source_id          int REFERENCES sources

-- Качество и модерация
confidence      real                   -- 0..1, из экстрактора
moderation      text DEFAULT 'pending' -- 'pending'|'approved'|'rejected'
moderation_note text
first_seen_at   timestamptz DEFAULT now()
updated_at      timestamptz
superseded_by   bigint                 -- id события-дубля, в которое схлопнуто
search_tsv      tsvector               -- (title + city + organizer), GIN-индекс

UNIQUE (norm_title, event_date, region_id)  -- нормализуемый индекс дедупа (через функциональный индекс)
```

**Индексные требования**: `BTree(event_date) WHERE moderation='approved' AND event_type='regional'`,
`GIN(search_tsv)`, `BTree(region_id, event_date)`.

### 4.5. Дедуп-алгоритм (`extractor/postpipe`)
1. Нормализация названия (lower, убрать пунктуацию/шума-слова «гонки», «соревнования»).
2. Ключ `(norm_title, event_date, region_id)` найден → добавить второй source_id в
   `event.sources[]` ( ارتباط event↔sources many-to-many `event_sources`), не создавать дубль.
3. Название различается, но URL регистрации совпадает → склеить тоже.

### 4.6. Прямые связи
```
sources 1—∞ raw_posts 1—1 extracted_json
events ∞—∞ sources (через event_sources: source_id, external_post_id, matched_at)
regions 1—∞ events
```

## 5. API (REST, v1)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/v1/events` | Параметры: `mode=regional\|national`, `region_id`, `city`, `date_from`, `date_to`, `status`, `has_prize`, `q` (поиск), `page`, `limit`. По умолчанию: `moderation=approved`, `event_date >= today`, сортировка `event_date asc` |
| GET | `/api/v1/events/{id}` | Детали события + список источников |
| GET | `/api/v1/regions` | Список субъектов + счётчик предстоящих событий каждого (для дропдауна/карты) |
| GET | `/api/v1/regions/{id}/events` | Синоним фильтра |
| GET | `/api/v1/stats` | Для дашборда/футера: «N предстоящих гонок в M регионах» |
| POST | `/api/v1/admin/events/{id}/approve\|reject` | Секрет в заголовке |
| PATCH | `/api/v1/admin/events/{id}` | Правка вручную импортированного события |
| POST | `/api/v1/admin/sources` | Добавить канал/паблик в парсинг |
| GET | `/api/v1/admin/raw-posts?processed=false` | Очередь модерации |

Кэш: публичные GET — 60 сек (Next.js ISR / nginx), инвалидации по updated_at.

## 6. UI/UX

### 6.1. Каркас
- Хедер: логотип, 2 вкладки-режима **«По регионам» / «Все соревнования»**, поиск.
- Фуoter: статистика, дисклеймер «информация собрана автоматически по открытому источнику».

### 6.2. Режим «По регионам»
- Сверху — карта России-субъектов (Yandex/GeoJSON): регионы с предстоящими событиями подсвечены жёлтым, счётчик бейджем; клик по региону — фильтр.
- Рядом/ниже — дропдаун «Область» (альтернативный ввод, обязательно по ТЗ) + чипы «Мои координаты — ближайшие N км» (опционально, можно отложить).
- Список карточек только выбранного региона; пустое состояние «В этом регионе пока анонсов нет — подпишитесь на уведомления» (сабскрипция после MVP).

### 6.3. Режим «Все соревнования»
- Единый список `event_type in ('national','major')` всех бэкграундов (федеральные, межрегиональные, кубковые этапы) + фильтры по статусу и датам.
- Внутри карточки — отдельный флажок «Всероссийский уровень».

### 6.4. Карточка соревнования (единый компонент `EventCard`)
```
┌──────────────────────────────────────────────────────┐
│ [Всероссийский]                    🟡 100 000 ₽      │  ← флаг уровня + призовой фонд (золото #FFC113)
│ ОТКРЫТЫЕ ГОНКИ ФГДР — ЛИПЕЦК                          │  ← название, Oswald-модный заголовок
│ РОО ФГДР Липецкой области                             │  ← организатор, полупрозрачный
│ 📅 22 ноября, 10:00      📍 Липецкая обл., Липецк     │  ← дата/время + гео
│ 🟢 РЕГИСТРАЦИЯ ОТКРЫТА                                │  ← статус-бейдж (варианты: 🟡 Анонс / 🔶 Регистрация закрыта / ⚪ Завершено / 🟠 Перенесено)
│ Призовой фонд: 100 000 ₽   |   null → «Уточняется»    │
│ [ Перейти к регистрации ]  [ Подробнее об ивенте ↗ ]  │  ← primary + secondary кнопки
└──────────────────────────────────────────────────────┘
```
- Призовой фонд: если `prize_fund_amount > 0` — крупная золотая плашка справа-сверху;
  `visibility=none` — серая «Без призового фонда»; `hidden/tbd` — «Уточняется».
- Статусы должны читаться без цвета (бейджи с текстом — доступность).
- Мобильный приоритет: карточки single-column, карта складывается в аккордеон.

### 6.5. SEO-требования (важный источник органики)
- SSR всех страниц списка; URL вида `/region/lipetskaya-oblast`, `/events/{slug}`.
- Schema.org `Event` (name, startDate, location, offers.url) на каждой карточке.
- Sitemap.xml по регионам и событиям, обновляется по крону.

## 7. Пошаговый план разработки

### Этап 0. Подготовка (1–2 дня)
- Согласовать API_ID/HASH Telegram (my.telegram.org), сервисный VK-токен, LLM-ключ.
- Собрать стартовый список источников: 15–40 каналов/пабликов
  (по ФГДР, региональным отделениям, известным сообществам — с "tier").
- Заготовить справочник `regions` (субъекты РФ + округа — фиксируемый сид).

### Этап 1. Скелет и данные (неделя 1–2)
- FastAPI + SQLAlchemy + Alembic + Docker Compose; миграции со схемой §4.
- Сид `regions`, `sources`.
- Коллектор Telegram (Telethon, прокси, фоновый джоб по расписанию), коллектор VK.
- Дедуп `raw_posts`, счётчики в telegraf-логах. Создание 100+ raw_posts как proof-of-work.

### Этап 2. Экстрактор (неделя 3–4)
- Regex-первичные паттерны (даты, суммы, ссылки, статусы) + pydantic-схема.
- LLM-вызов для непарсимых постов, structured output → валидация → `events` с confidence.
- Геокодинг локаций через Яндекс Geocoder (кэш в таблице `geo_cache`).
- Проверка на реальных постах: ≥70% автоматически, ≤30% в модерацию.
- Консольный/AJAX-дебаг: показывать raw_post, extracted_json, итоговое событие.

### Этап 3. Админ-модерация (неделя 5)
- `/admin`: список pending-событий, «Апрув / Репортаж / Править», пакетная обработка.
- Добавление/деактивация источников из админки.

### Этап 4. Фронт (недели 6–8)
- Next.js + Tailwind + shadcn: вкладки режимов, карта-регионы, дропдаун.
- Компонент `EventCard` со всеми плашками (фонд/статус/уровень).
- Фильтры, поиск, пагинация; ISR-кэш; SEO-разметка Schema.org; sitemap.

### Этап 5. Полировка и вывод (недели 9–10)
- Статусные авто-правила (`auto_status`): прошло date → finished, день X → ongoing.
- Sentry, uptime-пинг, логи коллекторов в Telegram-бот админа («парсер упал/собрал N постов»).
- Деплой: VPS (Нидерланды/казахстан — прокси для TG), домен, HTTPS, Lighthouse ≥ 90.
- Нагрузочный дым: 10k событий, пагинация/dyплей, <300ms p95 API.

### Этап 6. После MVP (бэклог)
- Email/TG-уведомления по регионам; избранное; календарные подписки (ICS).
- Скачивание .ics/csv, «дни до старта» в карточке.
- Партнёрский режим для организаторов (создать ивент вручную, минуя парсер).
- Авто-загрузка афиш-изображений в карточки; слайдер.
- Рейтинговая база пилотов (связь с результатами).

## 8. Риски и их обработка

| Риск | Митигация |
|---|---|
| Блокировка Telegram с РФ-хостинга | SOCKS5-прокси в конфиге коллектора, отдача API с любого хоста; ретраи с экспонентой |
| LLM «фантазирует» поля | Structured output + pydantic-валидация, confidence-порог, запрещённые null обязательных полей, ручная модерация |
| Посты не имеют года в дате | Эвристика «ближайшая будущая дата» + `date_time_precision` + плашка «дата уточняется» |
| Дубли событий из разных каналов | Дедуп по (нормализованный title, date, region) + по registration_url |
| Смена вёрстки сайтов/раскладок API | fail_count, алерт админу, пер-источник throttle |
| Юридика | Ссылки на первоисточник, цитирование <= 300 символов, дисклеймер, только публичные данные; не воровать афиши-картинки без ссылки |
| Один Telegram-аккаунт мягко банится за сканирование | Delay 1.2–2.0 сек между запросами, ночной режим, каналы качаются инкрементально (after=last_post) |

## 9. Метрики успеха MVP
- ≥ 70% событий экстрагируются без ручной правки.
- Свежесть: новое событие появляется на сайте ≤ 12 часов после поста.
- ≥ 3 регионов с живым списком на демо; 200 уникальных посещений/мес через 2 мес после запуска.
- Скорость главной страницы LCP < 2.5 с на 4G.
